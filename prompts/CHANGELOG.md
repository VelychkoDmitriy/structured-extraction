# Prompt changelog

Кожна версія — окремий файл `prompts/<version>.md` з розділами `## system` і `## user`.
Плейсхолдери: `{schema}` (JSON Schema `Resume`), `{guide}` (data/LABELING_GUIDE.md), `{resume_date}`, `{text}`.
Версія промпту записується в кожен результат (`prompt_version`) і в назву запуску `results/<model>__<prompt>__<sampling>/`.

## v1 — baseline
- Коротка інструкція: тільки те, що є в тексті; null / [] + `missing_fields`, нічого не вигадувати.
- Схема передається в промпті (однаково для обох моделей — чесне порівняння) і, для OpenAI, ще й як strict structured output.
- Правила розмітки (`{guide}`) свідомо **не** передаються: baseline показує, що модель робить без них.

## v2 — правила полів
Чому: у v1 найслабші поля — `work_experiences`, `employment_type`, `additional_educations`, `skills`, `city`. Модель сама вирішує, що вважати записом досвіду, курсом чи навичкою, і вирішує інакше, ніж еталон.
- Додано стислі правила з `LABELING_GUIDE.md` по кожному полю: критерій запису досвіду (2 з 3 ознак), формат дат і `is_current`, шкала рівнів освіти й мов, курси → `additional_educations`, навички як короткі теги, `employment_type` лише явно, `driver_license` ніколи не `false`.
- Гайд не вставляється цілком: у ньому є посилання на конкретні golden-документи та приклади з них. У промпті лише загальні правила, без прикладів із golden set.
- Перевірка — на dev-текстах (переглянуто вручну), підсумкова метрика — на golden.
