# Правила розмітки golden set

Схема — `schema.py` (`Resume`). Правило загальне: **беремо лише те, що є в тексті**. Немає в тексті → `null` або `[]`, і назва поля йде в `missing_fields`. Нічого не обчислюємо і не вгадуємо.

## Поля верхнього рівня
| Поле | Правило |
|---|---|
| `title` | Заголовок резюме (перший рядок), як написано. Невидимі символи (BOM) прибираємо |
| `age` | Вік числом («65 років», «Вік: 36»). Якщо є лише дата народження — обчислюємо повні роки на дату резюме (`resume_date` з manifest; модель отримує її разом з текстом) |
| `city` | Місто проживання без «м.», «с.», «г.», у називному відмінку («у м.Вінниці» → «Вінниця»). Країна — не місто. Якщо в тексті два міста, береться те, що в полі «Місто/Місто проживання». Скорочене місто лишаємо як є («Івано») |
| `desired_salary` | Сума за місяць у гривнях, числом. Погодинна ставка або інша валюта → `null` |
| `employment_type` | Тільки явне «повна/неповна зайнятість» |
| `work_location_preference` | «Дистанційно», якщо кандидат розглядає віддалену роботу, + міста з «Готовий працювати» |
| `driver_license` | `true`, якщо згадано права або категорію. Не згадано → `null` (не `false`) |

## Досвід роботи
- Окремий запис — конкретне місце роботи, де є **щонайменше дві з трьох ознак: посада, роботодавець, дати**. Тривалість («8 років», «3 months») — не дата. Перелік галузей/роботодавців без посад і дат («працювала в держказначействі, управлінні…») і посади без роботодавця й дат («посади продавець, касир») не розмічаємо.
- Роботодавець може бути описовим («кафе», «частный предприниматель»), але не галуззю («на будівництві», «у торгівлі»).
- Навчальні та портфоліо-проєкти (курси, «пет-проєкти», проєкти в школі програмування) — **не** досвід роботи.
- `company` — як написано, разом з формою («ТОВ "…"», «частный предприниматель»).
- Дати: `YYYY-MM`, якщо відомий місяць; `YYYY`, якщо тільки рік («1993.2014» → `1993`–`2014`). «дек. 2023» → `2023-12`.
- «по нині», «настоящее время», «present» → `end_date: null`, `is_current: true`. Кінця немає і поточність не сказано → `end_date: null`, `is_current: null`.
- `responsibilities` заповнюємо, але в метриках не оцінюємо.

## Освіта
- `level` зводимо до шкали: вища (бакалавр, магістр, спеціаліст, «вища освіта») / незакінчена вища / середня спеціальна (технікум, коледж, ПТУ, СПТУ, «середньо-технічна») / середня / `unknown`.
- Курси, тренінги, сертифікати → `additional_educations`, не в `educations`. Записуємо **навчальний заклад / школу** як написано («logosIT», «Hillel IT», «Dispatch42 School»), а не назву курсу — так само, як у датасеті KSE. Якщо школу не названо — назву курсу.
- Навчається зараз («навчаюся», «студент») → `незакінчена вища`.

## Мови
- `language` — українська назва малими літерами: English → `англійська`, Ukrainian → `українська`, Russian → `російська`.
- `level` за шкалою work.ua:

| У тексті | `level` |
|---|---|
| native, рідна, родной | `рідна` |
| вільно, fluent, C2 | `вільно` |
| просунутий, advanced, C1 | `просунутий` |
| вище середнього, upper-intermediate, B2 | `вище середнього` |
| середній, intermediate, B1 | `середній` |
| початковий, basic, elementary, pre-intermediate, A1–A2 | `початковий` |
| рівень не вказано | `unknown` |

- Мова, якою написано резюме, сама по собі **не** означає знання мови.

## Навички
- Навичка — **короткий тег**, як у датасеті KSE: інструмент, технологія, програма або особиста якість («1С», «Excel», «Docker», «Комунікабельність»). Кожен пункт окремо, як написано.
- Технологія, яку кандидат прямо називає як використану (і в описі проєктів теж), — це навичка.
- Обов'язки й описи діяльності («Повний бухгалтерський супровід ТОВ…», «опыт решения нестандартных ситуаций») — **не** навички, навіть під заголовком «навички».
- Можливості компанії, а не кандидата (f17), навичками не є.

## `missing_fields`
Поля верхнього рівня зі значенням `null` або `[]`.
